# math-perceptions — Astro Study Site Structure

**Date:** 2026-07-22
**Status:** Approved design (pre-implementation)
**Repo:** https://github.com/vageez/math-perceptions.git
**Supersedes/patches:** `ASTRO_SETUP.md` (see §9)

---

## 1. Purpose

Build one Astro + Starlight website that helps a student study math, starting
with Grade 10. Content is organized under a **namespace hierarchy** so future
levels (Grade 11, etc.) can be added without re-architecting. The site must stay
simple: no accounts, dashboards, or publishing abstractions in the first version.
The existing Markdown in `docs/` remains the source of truth.

## 2. Key decisions (resolved in brainstorming)

| Decision | Choice |
|---|---|
| One site or many? | **One unified Starlight app.** Namespaces are directories in the content tree, not separate apps. Single search + sidebar across all namespaces. |
| Namespace path | `levels/<level>/…` — e.g. `levels/grade10/`. |
| Unit page shape | **Flat** — the unit folder carries the topic name; pages sit directly inside. Maps 1:1 onto existing `docs/unit-1-linear-relations/*`. |
| App location in repo | `site/` subfolder (source/research/reviewer files stay separate at repo root). |
| Display vs URL | URL segment `grade10`; sidebar/landing display "Grade 10". |
| Hosting | GitHub Pages **project** site → `base: '/math-perceptions'`. |

## 3. Repo & local mapping

The on-disk folder `~/Documents/math-grade10` becomes the `math-perceptions`
repo — `git init` in place, wire the (currently empty) remote, first commit,
push. The disk folder name need not match the repo name; nothing is moved or
re-cloned.

`.gitignore` covers Node/Astro build artifacts: `node_modules/`, `dist/`,
`.astro/`, `.DS_Store`.

## 7. Site configuration

### 7.1 Sidebar

Top tier = namespaces. Group **Grade 10**; unit sub-groups autogenerated from
directories, ordered by frontmatter `sidebar.order` (gaps of 10). `grade11`
becomes a sibling top group later. One search box spans all namespaces.

### 7.2 Math rendering (corrected)

The config shown in `ASTRO_SETUP.md` §7 is invalid (`markdown.processor` /
`unified` import do not exist in Astro). Correct approach:

Install: `remark-math rehype-katex katex` (do **not** install
`@astrojs/markdown-remark`).

```js
// astro.config.mjs
import { defineConfig } from 'astro/config';
import starlight from '@astrojs/starlight';
import remarkMath from 'remark-math';
import rehypeKatex from 'rehype-katex';

export default defineConfig({
  site: 'https://vageez.github.io',
  base: '/math-perceptions',
  markdown: {
    remarkPlugins: [remarkMath],
    rehypePlugins: [rehypeKatex],
  },
  integrations: [
    starlight({
      title: 'Math Perceptions',
      customCss: ['./src/styles/custom.css'], // includes KaTeX CSS import
      sidebar: [
        { label: 'Start Here', link: '/' },
        {
          label: 'Grade 10',
          items: [
            {
              label: 'Unit 1 — Linear Relations',
              autogenerate: { directory: 'levels/grade10/unit-1-linear-relations' },
            },
          ],
        },
      ],
    }),
  ],
});
```

> Verify the exact Starlight sidebar `autogenerate` shape against the installed
> version before committing config — the nested `items`/`autogenerate` form in
> `ASTRO_SETUP.md` §7 must be checked.

`src/styles/custom.css` begins with `@import 'katex/dist/katex.min.css';`.

### 7.3 Content collection

Single Starlight `docs` collection via `docsLoader()` / `docsSchema()` in
`src/content.config.ts`. Directories create the sections — do **not** make one
collection per namespace or unit.

## 8. GitHub Pages deployment

- `astro.config.mjs`: `site` + `base` as above.
- `.github/workflows/deploy.yml` using `withastro/action`, building from `site/`.
- Repo `gh` token already has `workflow` scope, so pushing the workflow is fine.
- **One-time manual step (user):** enable Pages (Settings → Pages → Source:
  GitHub Actions).

## 9. Migration — copy, never delete

`docs/` stays authoritative until Unit 1 is reviewed and approved. Per file:
copy into the new tree → add frontmatter → convert internal `.md` links to clean
`/levels/grade10/…` routes → validate. Only archive originals after approval.

Frontmatter contract, page section sequence (question → hero → analogy →
meaning → formula → worked example → recognition table → mistakes → quick check
→ checklist), and diagram accessibility rules carry over unchanged from
`ASTRO_SETUP.md` §9–§11.

## 10. Phasing

- **Phase A — Shell:** git init + `.gitignore` + first commit + push; scaffold
  Starlight in `site/`; corrected KaTeX config; minimal CSS; student home page;
  verify starter builds.
- **Phase B — Unit 1:** copy 8 pages into
  `levels/grade10/unit-1-linear-relations/`; move review file to `review/`; add
  frontmatter + clean links; build and visually check every page.
- **Phase C — Deploy:** base path + workflow; enable Pages; confirm live.
- **Phase D — Later units/namespaces:** one complete unit at a time.

## 11. Definition of done (Phase A–C)

Production build finishes without errors; all Unit 1 pages appear in order under
`/levels/grade10/unit-1-linear-relations/`; internal links work; formulas render
on desktop and mobile; diagrams don't overflow; hidden answers open/close;
search finds "slope," "parallel," "perpendicular," "elimination"; reviewer files
are unreachable from the public site; the live GitHub Pages URL loads.
